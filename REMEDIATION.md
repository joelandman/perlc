17. ~~**Fix D38b: `s/$/text/` segfault (zero-width regex-substitution match)**~~ — FIXED

23. ~~**Fix D23: regex literals collapsed `\\` into a single `\`, silently changing match semantics**~~ — FIXED
    - Root cause: the lexer's `readRegex()` special-cased `\\` in the source and collapsed it to a single `\` in the pattern string handed to PCRE2, while passing every *other* backslash-escaped pair (`\d`, `\s`, `\/`, etc.) through unchanged (both characters) — an inconsistency, and wrong. PCRE2 needs to see `\\` exactly as written to interpret it as "one literal backslash"; collapsing it first turned the following character into part of an unintended escape sequence. `/a\\d/` (literal backslash then "d") silently became `/a\d/` (the digit metaclass) with no error — a silent, wrong-match bug for any pattern containing a literal backslash.
    - Fix: removed the special case entirely. Every backslash-escaped pair is now passed through to PCRE2 unchanged, exactly like the general (non-`\\`) branch already did. PCRE2 does its own escape interpretation and tolerates a redundant escape of the delimiter character (`\/`) fine — no lexer-side special-casing needed for that either. `s///`'s lexer (`readSubst`) never had this bug — its equivalent loop already passed every escaped pair through unconditionally, so no change was needed there.

24. ~~**Fix D35: `Carp::croak`/`confess` bypassed `eval` via `exit(1)`, plus a crash and a data-corruption bug found while fixing it**~~ — FIXED
    - Root cause (D35 itself): `perl_carp_croak()` called `fprintf(stderr,...)` then `exit(1)` directly, completely bypassing the die/eval/longjmp mechanism. The standard `eval { croak(...) }` pattern for turning a library error into a catchable exception killed the entire process under perlc instead of setting `$@` and continuing.
    - Fix: route `perl_carp_croak()` through the existing `perl_die()` instead of duplicating (and getting wrong) its own exit logic. `perl_die()` already had the correct dual behavior — longjmp to the nearest eval (setting `$@`) if one is active, or print to stderr and `exit(1)` at top level if not. `codegen.cpp` already routes both `croak` and `confess` through `perl_carp_croak`, so both are fixed by this one change.
    - **Blocking crash found and fixed as a direct dependency**: the standard error-rethrow idiom `eval {...}; die $@ if $@;` passes `$@` to `die()` as the exact same cell it was just written into (`perl_get_dollar_at()` returns the live global's address, not a copy) — i.e. self-assignment. Testing that surfaced a much more fundamental bug: plain `$x = $x;` segfaulted perlc entirely. Root cause: `perl_assign()` freed the assignment target's old payload (`free(dst->sval)`) *before* reading/cloning from `src` (`strdup(src->sval)`); when `dst==src`, that free invalidated `src` too, so the following `strdup` read from memory that was already freed (and NULLed), crashing. Fixed by making `dst==src` a guaranteed no-op — self-assignment never needs to change anything, so skipping the free+reclone entirely is both correct and cheaper.

33. ~~**Fix D57: a self-recursive sub matching the AST-level inliner's shape hung/crashed the compiler at compile time**~~ — FIXED
    - Root cause: `tryEmitInline()` (codegen.cpp) unconditionally inlines any call whose target name is a key in `inlineSubs_` (subs whose body is exactly `my (@params) = @_; return expr;`), with no self-reference or cycle guard at all. For an ordinary (non-recursive) chain of inlinable subs this terminates fine, bounded by the finite number of subs in the program. But when the return expression being inlined contains a call back to the *same* sub (direct self-recursion) — or, transitively, to another inlinable sub that eventually calls back to it (mutual recursion) — `tryEmitInline()` recurses into itself operating on the exact same, unchanging AST node every time. This is *static, compile-time* infinite recursion in the compiler's own C++ call stack (not a runtime loop in the generated program), and was observed to crash with an LLVM "please submit a bug report" stack dump.     - Fix: restructured `compile()`'s inlineable-sub detection into two phases. Phase 1 is unchanged in spirit (same shape-matching logic as before) but now populates a local `candidates` map instead of `inlineSubs_` directly, so nothing becomes "live" for `tryEmitInline()` until cycle analysis has run. Phase 2 adds two new static helpers: `collectCalls(const Node &n, std::vector<std::string> &out)` walks every child-holding field of an expression subtree (same field set as `collectSubDefs`) and records the name of every `NK::Call` found; `dfsFindCycles(...)` runs standard 3-color DFS cycle detection (0=unvisited, 1=on the current DFS stack, 2=fully explored) over a call graph built by, for each candidate, calling `collectCalls()` on its body expression and keeping only edges whose target is *also* a candidate (an edge to a non-candidate sub can never be part of a cycle, since that call just becomes an ordinary bounded function call — no need to track it). Finding an edge back to a node still marked "on stack" means everything between that node and the top of the stack is in a cycle; a direct self-recursive sub is simply the degenerate case where the back-edge points at the node currently being visited.       - **Resource lifecycle**: `dlopen()`ed do-lib handles are tracked in a new `__thread` linked list (mirroring the pre-existing pattern used for XS module handles) and `dlclose()`d only at `perl_cleanup()` (process exit) — a do'd file's subs must stay callable for the rest of the process's lifetime, matching real Perl.       - **Single-quoted strings ran through the identical escape-resolution switch as double-quoted strings**, so `'a\nb'` incorrectly produced the 3 characters `a`, newline, `b` instead of real Perl's 4 *literal* characters `a`, `\`, `n`, `b` (single-quoted strings only ever recognize `\\` and `\'` as real escapes; every other backslash sequence, including `\n`, `\t`, `\$`, etc., stays as two literal characters, backslash included). 41. ~~**Fix D28: `sort`/`reduce` comparator blocks always rebound `$a`/`$b` to fresh locals, ignoring an outer lexical `my $a`/`my $b` that should shadow them**~~ — FIXED
    - Root cause: real Perl's `sort`/`reduce` comparator `$a`/`$b` are dynamically-aliased *package* variables, not a fresh lexical scope the construct introduces itself. If an earlier `my $a`/`my $b` is already declared in an enclosing lexical scope, it permanently shadows the package variable's name for all later code in that scope — including a comparator block compiled after it, since Perl resolves `$a`/`$b` references via ordinary compile-time lexical scoping, the same as any other variable (this is the well-known real-Perl footgun real Perl itself warns about: `"my $a" used in sort comparison`). perlc instead always unconditionally declared its own fresh `$a`/`$b` locals for the comparator at both sites that need them, winning any lookup regardless of what was already in scope — a real, silent behavioral divergence from actual Perl semantics, not merely a missing warning.
    - Fix: both binding sites now check whether `$a`/`$b` is already visible from an enclosing scope before declaring their own, and skip the declaration if so — letting normal variable lookup fall through to the outer shadow exactly as real Perl's lexical scoping would:
      - `reduce {}`'s block (codegen.cpp, compiled *inline* in the current function since it's just a loop over the list, with no separate function or scope reset) now uses the fully general `lookupVar("a")`/`lookupVar("b")` — since its scope stack is left completely intact, this correctly sees a shadow from *either* file scope or any enclosing sub/block scope.
      - `sort { BLOCK }`'s custom comparator (`case NK::SortFunc`, `mode=="custom"`) is compiled as a genuinely *separate* LLVM function (`cmpFn`), since it must be passed as a real C function pointer to the underlying `qsort()`-based sort routine (`perl_sort_custom`) — its scope stack is fully reset (`scopes_={}` etc.) before compiling the comparator body, so a `lookupVar()`-based check can't reach back into the caller's scope at all. Its check is therefore narrower — `fileScalarGlobals_.count("a")`/`("b")`, the *file-scope* global-variable map that survives the scope reset — meaning it only correctly shadows an outer `$a`/`$b` declared at true file scope, not one declared inside an enclosing sub or block. This narrower gap (an enclosing *sub/block*-scoped `my $a` shadowing a sort comparator) remains open and would need real closure-capture machinery wired into the comparator function, the same kind `AnonSub` already has elsewhere — tracked separately as part of newly-logged **D61** below, since it turned out to be one instance of a broader, pre-existing limitation of sort's comparator.

Real Perl's `sort` has used a stable mergesort since 5.8; perlc's `sort` uses C's `qsort()` (unstable, pivot-choice-dependent) — for a degenerate/non-transitive comparator, the two legitimately produce different final permutations (and even a different number of comparator invocations), independent of whether the shadowing itself is handled correctly. Confirmed via `git stash` that this reproduces identically with this fix's own changes reverted, so it's entirely pre-existing and unrelated to D28's actual $a/$b-shadowing logic — it's the *same underlying architectural gap* (sort's comparator has no closure-capture machinery at all) that also explains why this fix's own sub/block-scope shadowing case remains open above; `map`/`grep`/`reduce` blocks are all compiled inline, sharing the enclosing scope stack directly, so none of them have any version of this issue. Worked around in this fix's own test file by moving the affected section's variables to true file scope instead, and reordering it to come *after* the file's other, no-shadowing sort regression checks (so the file-scope `$a = "SHADOW"` this section relies on doesn't leak into and break those unrelated, earlier-appearing regression sections).
